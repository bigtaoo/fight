# 美术：水墨风 + AI 出图

## 方向

- 水墨为主，**朱砂红是主角专属的强调色**（围巾等），敌人只用墨色、靛青、灰，不出现红色
  （沿用 standing"主角暖色、敌人冷色"的可读性规则）。
- 侧面视角朝右，向左时水平镜像。
- 游戏内尺寸（1080p 逻辑单位）：主角高约 240，杂兵 200～260。

## 出图流程（沿用 standing）

1. prompt 写成 `.txt`，放在产出图旁边。
2. `tools/generate_image.sh <out> <prompt.txt>`：Mistral Agents API 调用 FLUX 文生图（约 1024×768）。
   `tools/edit_image.sh <in> <out> <prompt.txt>`：以参考图做编辑，输出保持输入比例。
   密钥在 `~/.vibe/mistral_curl_key*.conf`，`mistral_failover.sh` 负责限流时轮换 key。
3. 人工挑选；落选的写清原因。
4. 抠图：水墨用 `tools/ink_cutout.py`，而不是 standing 的 `cutout.py`。
   后者把与边缘连通的浅色低饱和像素当背景，会吃掉墨晕和飞白。
   `ink_cutout.py` 让人物主体保持不透明（人群重叠时不会互相透过去），主体外的墨迹按纸色做 color-to-alpha，保留半透明。
5. 可读性：`tools/ink_scene_test.py` 把人物按 240 和 120 两种高度，贴到浅纸、中灰墨晕、深色洞窟三种地面上。

## 动画（沿用 standing）

- 主角、精英、Boss：剪纸骨骼。先 edit 出一张侧面 A-pose（四肢离开身体）→ 拆件 → `.tao`。
  换装、时装只需替换部件贴图。
- 杂兵：原计划单张图做软边区域变形、烘焙成帧序列（standing `tools/bake_mob.py`）。山贼实际也走了骨骼流程（见"R3 山贼骨骼"），
  同一套工具、同一种画法，成本并不比帧序列高；以后种类多了再评估帧序列。
- 判定框在 animator 里逐帧编辑，导出给引擎；渲染骨骼不参与判定。

水墨特有的风险：飞白、墨晕跨过关节，拆件后转动关节时会露出断口。拆件那一步要专门验证。

## 风格轮次

### R1（`art/style_r1/`）

同一个角色（江湖剑客，侧面朝右，持剑低姿态），四个方向：

| 文件 | 方向 |
|---|---|
| `a_xieyi` | 写意：粗放笔触、飞白、大量留白，黑灰墨 + 朱砂 |
| `b_gongbi` | 工笔淡彩：细匀墨线 + 透明矿物色（靛青、石灰、浅赭）|
| `c_brushcel` | 笔触描边 + 平涂：粗细变化的墨线外轮廓，平涂墨灰/靛青/米白，一层硬边墨影 |
| `d_pomo` | 泼墨剪影：几乎全黑的墨色剪影，用留白线勾出五官、手、衣褶、剑刃 |

可读性对比：`art/style_r1/scene_test.png`。

观察：

- 四张都没画成纯侧面，而是 3/4 侧身。DNF 本来就是这样，保留。
- FLUX 不听"白底、无落款、无地面阴影"：a 加了黑边、落款和印章；b 是灰底；b、c、d 都有地面阴影或墨池。
  `ink_cutout.py` 已能处理灰底、黑边、地面阴影，但落款和印章只能重新生成或手工擦掉。
- a 写意：最像水墨画，但袍子的墨晕是半透明的，人群重叠时会糊在一起；边缘破碎，拆件难度高；出图不稳定。
- b 工笔：画出来是普通平涂插画，没有工笔特征。淘汰。
- c 笔触平涂：最干净，最好拆件，但看起来像日系动画，墨味最弱。
- d 泼墨剪影：轮廓最强，在浅纸和中灰上都很醒目，朱砂红非常跳；剪影内部细节少，拆件接缝反而容易藏。
  缺点是在深色背景上几乎消失。

**已定（2026-10-08）**：

- 角色走 d（泼墨剪影）。
- 世界观为"画卷世界"：场景永远是浅到中灰的纸面，不出现纯黑背景；夜晚、洞窟用靛青灰墨晕表现，保持中等亮度。
- 主角为浓墨 + 朱砂；敌人用较淡的灰墨、靛青，不用纯黑，与主角拉开明度差。
- 所有角色都画成朝右，游戏里镜像得到朝左（FLUX 不听"朝左"）。

### R3 骨骼（`art/rig_r3/`，2026-10-08）

用户反馈 R3a 走路是"滑"的（贴图脚不动），于是提前做骨骼。主角已换成骨骼动画；山贼、木桩仍用 R3a 姿势图。

流程（每一步都可重跑）：

1. `python -I tools/mannequin.py art/rig_r3/mannequin.png art/rig_r3/mannequin_joints.json`：代码画灰色 A-pose 人偶。
2. `tools/edit_image.sh mannequin.png hero_apose_X.png hero_apose_X.txt`：FLUX 在人偶上画剑客。
3. 选定的图镜像成朝右，存为 `hero_apose.png`。
4. `python -I tools/draw_sword.py art/rig_r3/sword.png`：代码画剑。
5. `python -I tools/split_parts.py art/rig_r3/split.json art/rig_r3/parts`：按多边形拆成 16 块，`parts/preview.png` 是拼回图和爆炸图。
6. `python -I art/rig_r3/anims.py` 生成 `hero_tao.json`（动画）→ `python -I tools/pack_tao.py art/rig_r3/hero_tao.json art/rig_r3/hero.tao client/public/art/hero`。
7. 检查：`tools/pose_test.py`（`rig.json` 里的测试姿势）、`tools/anim_sheet.py`（按客户端的采样规则把每段动画画成联络表）；游戏里 `?zoom=3` 镜头跟拍主角。

观察：

- 第一轮人偶头太大（约 5.5 头身），FLUX 三张都画成了小孩（`r0/`，弃用）。人偶改成 7.5 头身后都是成年人。
- edit 会保留人偶的大致轮廓，但不严格：手臂收拢了一些，四张里有三张朝左（镜像即可）。
- 选 `hero_apose_D.png`：四肢和身体之间的空隙最清楚，腿分得最开。B/C 朝左、手臂贴身；E 画成了短裤。
- 风格比 R1 的 d 更"平"：剪影干净、墨块均匀，少了泼墨的湿笔感，但拆件和转关节都很干净。墨迹感暂时靠动态墨点补。
- FLUX 不按要求空手画剑会画乱，所以剑是代码画的独立部件（挂在前手上），挥刀时只转手臂和剑。
- 拆件的遮挡区（被袍子、躯干盖住的大腿、肩、肘）用该部件最深的墨色平涂，不用 inpaint：剪影内部几乎全黑，inpaint 会把边缘的浅色和灰色衣褶拖进来。
- 骨骼：躯干、头、围巾、腰带、袍子、前后上臂/前臂/手、剑、前后大腿/小腿，共 17 根骨骼。

客户端（`client/src/game/bodyView.ts`）：

- 运行时从 standing 移植（`client/src/game/tao/`），加了 `seek()`：直接设定片段时间，而不是按真实时间播放。
- 招式片段的时间 = 状态内 tick（hitstop 时不走），所以刀在判定帧上落下，打中时跟着停住。片段关键帧用 tick 写，对齐 `engine/content.ts` 的帧数据。
- 走、跑的片段时间 = 走过的距离 ÷ 一个循环的步幅（走 176、跑 250 世界单位），所以脚不会滑。
- 跳跃按竖直速度在"上升/下落"两个姿势间插值；浮空翻滚仍在代码里整体旋转。
- `?poses` 切回 R3a 姿势图对比。

动作张力（用户反馈第一版出剑"很平、没力道"，不如 R3a 姿势图）：

- 原因：人站得笔直、两腿并拢，只有手臂在挥；收刀时剑尖指地、手臂缩在身前。R3a 的图全是低重心大弓步，整个身体压进刀里。
- 改法（`anims.py`）：待机改为低重心守势；出招时前腿弓、后腿蹬直，躯干扑向刀的方向，后手往反方向甩开；起手先向后仰蓄力一帧，刀一两帧内挥过去，收刀时手臂打直、剑斜指前下方，保持几帧再慢慢收回。打中那一帧是 hitstop 定格的那一帧，要是最有力的剪影。
- `pose()` 默认自动压低 root，让较低的那只脚贴地（宽站姿会下沉而不是悬空）；跑、跳、起身这类离地或跪姿用 `plant=False`。
- 受击的淡入改为和招式一样快（0.04 秒），否则"被打得一甩"会被抹平。
- 第二轮（用户："好了很多，但张力还不够，剑太短"）：打中帧后手完全甩直，和剑连成一条长斜线；弓步更开；袍摆向后拖（`robe`）；整个人比脚多冲出去一点（`root` 的 x，纯表现，不动判定）；蓄力帧更往后仰。
- 剑太短的真正原因：代码画的剑按握把放进原画坐标后，剑尖伸出了原画画布，被裁掉了大半。`split_parts.py` 现在给代码画的部件留足边距。剑长改为 820（约身高的 3/4）。

拆件穿透（用户："胸口有很多白点"）：

- 盖在别的部件上的部件（腰带垂穗、腰带结、围巾）被从袍子、躯干里挖掉了，一甩开就露出背景。袍子、躯干在这些位置补了 `hidden` 平涂。
- 衣服上的白色镶边（领口、下摆）被去纸当成纸变半透明。`split_parts.py` 现在把剪影内部（含小的封闭孔）一律设为不透明、保留原画颜色，只有外轮廓留柔边。
- 下摆白边横穿整条腿，膝盖处的补洞被剪影裁掉，弯腿时裂开。新增 `caps`：不受剪影限制的关节盖（膝盖用圆盘）。
- 检查方法：把联络表的底色换成纯蓝（`tools/anim_sheet.py` 里 `render()` 的 `paper_rgb`），任何穿透都会一眼看出来。
- 补完穿透后仍有白点（用户："原图里的衣襟的线条，但是缩小之后成了杂点"）：衣襟、下摆、袖口的白色镶边在原画里有 2~3 像素宽，游戏里人物约缩到图集的 1/3，细线落到不足一像素，取样时忽有忽无，看起来就是闪烁的白点。两处一起改：
  - 拆件时把轮廓内的浅色、低饱和颜料往墨色压（`split.json` 的 `pale_keep: 0.3`，只保留 30% 的亮度差），白边变成暗灰色的衣褶线；红色腰带、围巾饱和度高，不受影响。
  - 客户端加载图集时开 mipmap（`autoGenerateMipmaps`），缩小时按区域平均而不是跳着取样。图集部件之间的空隙从 2 像素加到 8 像素，免得低级 mipmap 把相邻部件的颜色混进来。

已知问题：袍子下的大腿是平涂色块，大幅迈步（突进、奔跑）时能看出来；前手是张开的，握剑不像；躯干只能在腰部弯折，前倾过大时像驼背。木桩还没上骨骼（仍用 R3a 姿势图）。

### R3 山贼骨骼（`art/rig_bandit/`，2026-10-08）

原计划杂兵用帧序列（standing `bake_mob.py`），实际直接复用主角的骨骼流程更省事，也和主角同一个画法。山贼已在游戏里用骨骼动画。

流程（每一步都可重跑）：

1. `python -I tools/mannequin.py art/rig_bandit/mannequin.png art/rig_bandit/mannequin_joints.json --build stocky`：壮汉体型人偶。
   髋、膝、脚的高度和主角相同；肩更宽、四肢更粗、短褂只到膝上、光头不带发髻。
2. `tools/edit_image.sh mannequin.png bandit_apose_X.png bandit_apose_X.txt`，选定的图存为 `bandit_apose.png`。
3. `python -I tools/draw_sword.py art/rig_bandit/dao.png dao`：代码画刀（宽背单刃刀，灰靛色，刀柄挂靛青布条，不用红）。
4. `python -I tools/split_parts.py art/rig_bandit/split.json art/rig_bandit/parts`：拆成 14 块（没有围巾和腰带）。
5. `python -I art/rig_bandit/anims.py` → `python -I tools/pack_tao.py art/rig_bandit/bandit_tao.json art/rig_bandit/bandit.tao client/public/art/bandit`。
6. 检查：`anim_sheet.png`（`tools/anim_sheet.py`）；可读性：`python -I tools/rig_scene_test.py art/rig_bandit/scene_test.png art/rig_r3/parts:240 art/rig_bandit/parts:250`。

观察：

- prompt 写"淡墨、靛青"时，FLUX 画成了写实的淡彩素描（`r0/` 的 A、B、C，弃用），和 R2 的 `mob_bandit_v0` 一样。
  只有写"纯黑剪影"才会画成剪影，所以改为让 FLUX 画黑剪影，再由 `split.json` 的 `tint` 把黑墨换成靛灰（纸白不变）。
- 选 D：剪影和主角是同一种画法，前臂、两条小腿与身体之间都有空隙。E 是同一 prompt 换密钥出的第二张，F 更写实，两腿连成一块。
- 人偶的手臂在成图里仍然收拢了一些，后臂上段贴着身体，靠 `hidden` 补；画在身体前面的部件（前臂、前手）的补块在静止时看得见，
  平涂会在靛灰身体上露出方块，所以这些部件用 `hidden_fill: "copy"`，补块直接沿用原画。
- 动作（`anims.py`，姿势工具和主角共用 `tools/rigpose.py`）：驼背、手肘外张的莽汉，不是剑客。
  劈砍 40 帧，前 15 帧把刀拖到肩后高举并停住，这是给玩家的明显预警；第 16 帧扑出，第 17 帧（判定帧）落刀，前腿弓、后腿蹬直。
- 游戏里身高 250（主角 240），步幅一个循环 141 世界单位（`bodyView.ts` 的 `RIG_SIZE`）。

可读性复测（`scene_test.png`：浅纸、中灰墨晕、靛青夜色三种地面，桌面和手机两种尺寸，单人和"主角在前、山贼两两重叠"的人群）：

- 第一版（靛灰 `[78, 86, 104]`，无勾边）：浅纸可以，中灰对比偏低；**夜色里山贼和地面同明度，几乎消失**；两个山贼重叠时糊成一团。
- 加深墨勾边后，夜色的桌面尺寸能看清，手机尺寸仍发虚。
- **定稿**：山贼提亮到 `[124, 132, 152]`，外轮廓内侧加 14 像素的深墨勾边（`outline`）。三种地面、两种尺寸都看得清，重叠的山贼也能靠勾边分开；
  主角浓墨 + 朱砂、山贼浅靛灰 + 墨线，一眼能分出敌我。
- 代价：提亮后山贼脸部和衣褶的细节变淡，偏"影子"感。勾边只在整个人物的外轮廓上，部件转开后露出的内侧边缘没有勾边。

配色第二版（用户反馈"配色太不好"）：

- 问题：整个人一种靛灰，像一团淡蓝色的影子，看不出衣服、皮肤，也不像山贼。
- 做法：`split.json` 的 `regions` 按服装分区上色（淡彩）。原画里衣服的白色镶边天然把黑剪影分成小块（头巾、两只袖子、两条前臂、手），
  每个区域从种子点出发，不跨白线地占领小块，再用多边形截断白线没分开的地方（脸和脖子、腰带、裤子和靴子）；
  没被占领的像素（包括白线本身）取最近区域的颜色，接缝稍微模糊，像湿笔渗色。
- 试了三套（花青短褂 + 赭石腰带、赭石短褂 + 花青头巾腰带、土黄短褂 + 墨色头巾腰带），三套在三种地面上都比第一版清楚（对比图 `palette_variants.png`：从上到下浅纸、中灰、夜色，每行左起主角和三套）。
  **定稿第二套**：赭石短褂 `[124, 80, 52]`、皮肤淡赭 `[178, 130, 92]`、花青头巾和腰带 `[44, 58, 88]`、深褐裤 `[60, 54, 50]`、墨色靴 `[30, 28, 28]`；
  勾边减到 10 像素。暖色的山贼和黑衣朱砂的主角、冷色的地面都拉得开；花青和敌人血条同色，作为敌方的记号。
- 分区上色后，画在别的部件前面的补块（头的脖子、躯干的腰带处、小腿的膝盖圆）在静止时露出平涂的色块，这些部件也改用 `hidden_fill: "copy"`。

### 动作过渡（2026-10-08）

用户反馈"动作切换时主角抖动厉害"。用无头模拟（机器人打一分钟、60 帧/秒，逐帧记录剑尖位置）找到三处，见 `client/src/game/bodyView.test.ts`：

- **打中时动作往回跳一帧**（最大的一处，剑尖来回 150–230 像素）：位置是在上一帧和这一帧之间插值的，动作时间却按"这一帧 + 插值"算，领先一帧；
  打中进入停顿（hitstop）时退回这一帧，停顿结束再往前跳。现在动作时间和位置一样落后一帧插值，停顿时停在这一帧，前后连续。
- **连招从别的姿势切入**：普攻二段剑已经抬起一半时就能接三段，三段第一帧却是剑在下方，0.04 秒的过渡几乎是瞬切。
- **过渡被打断**：上一个过渡还没走完又切动作时，旧的混合姿势被丢掉。

现在的过渡（`TaoActor`）：切换时冻结屏幕上正在显示的姿势，从它过渡到新动作；用 ease-out，大部分在头一两帧完成，出招仍然跟手；
角度走短的那一边；同一个单次动作重新开始（连续受击）也算切换。时长：出招 0.08 秒，受击 0.05 秒，其他 0.12 秒。
走路、跑步从站立开始时从步态的第一步起，不再从累计步数的任意位置开始。

结果：剑尖来回跳的次数 141 → 47，最大 229 → 53；剩下的都是招式本身蓄力时的回拉。

连按普攻时后手乱甩（用户反馈）：不是过渡的问题，是动作幅度。三段普攻里后手每段都先往前甩、再甩到身后
（一段 35° → -100°，二段又甩回 30° 再到 -75°，三段从身后抡到头顶 165°），每段 130–240 度。单按一次只看到一个来回；
连按时每 6 帧接一段，后手每秒来回约 2 次、移动距离比握剑的手还大。
现在后手只在小范围内反向配合（`anims.py` 的 HIT1/HIT2/HIT3 和各段蓄力帧），蓄力时停在上一刀留下的位置附近，只有三段双手上举时举过头顶。
连按 9 秒：后手每秒移动 1634 → 671（握剑的手 1456），来回 17 → 0 次。

### 手臂与握刀（2026-10-08）

用户反馈"主角拿剑的手上臂缺了一块，上下臂协调很怪；怪物拿刀像马上要掉"。三处原因：

- **主角上臂太细**：原画是四分之三侧身，前臂的肩部和躯干画成了同一片黑，拆件时上臂只切到袖缝外面那一条（肩下只有约 10 像素宽），
  肩关节也放在了这条的边上。手臂一抬，肩下就只剩一根细棍，接着下面宽大的袖子。现在 `split.json` 的 `arm_f_upper` 往里包进袖缝内侧到肩头那一块
  （躯干里也保留同样的像素，抬臂时下面不会露空），肩关节移到肩膀中间（552,355 → 532,350），`anims.py` 里上臂的静止方向随之 16° → 22°。
- **肘关节反折**：五个关键帧里前臂比上臂更往后（`af` 第二个数小于第一个，最多反折 25°），看起来像胳膊肘往外掰：
  普攻一段挥下中途、二段蓄力、上挑蓄力、跳斩两帧（突刺的后手也有 10°）。全部改成肘只往前弯。规则：`af`/`ab` 的前臂方向不小于上臂方向。
- **山贼握刀**：站立和走路时刀的方向（45°）比前臂（60°）还往下，刀顺着胳膊的线往下垂，像只用指尖捏着刀柄。现在刀从拳头里朝前伸出
  （站立 100°，走路 96–104°，受击 70–85°），刀柄横穿拳头，刀穗从拳底露出。
