DNF 式 2.5D 横版动作页游。网络与反作弊沿用 `D:\funny` 的 lockstep 框架并加入回滚，
美术沿用 `D:\standing` 的 AI 出图流程，风格改为水墨。

文档索引：

- [MVP.md](MVP.md)：当前阶段，最小化验证的范围与验收标准
- [ART.md](ART.md)：水墨美术方向、出图流程、风格轮次记录

## 已定决策

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | PixiJS v8 + Vite + TypeScript；网页 + 微信小游戏 | standing、daydayup 已在 v8 上跑通微信 |

| D4 | 美术为水墨风，AI 出图 | 见 ART.md |

## 架构

```
dnf/
├── engine/      确定性模拟（客户端与服务器共用源码）
├── client/      PixiJS v8：渲染、输入、预测与回滚、UI
├── server/      节拍器中继 + 复算 verifier + 账号背包掉落（MVP 阶段合成一个进程）
├── tools/       出图、抠图、拆件、打包、可读性测试；animator（判定框轨道）
├── art/         源美术、风格轮次、prompt
└── design/      设计文档
```

正式版本按 funny 的方式拆服务（gateway / matchsvc / gamesvc / verifier / metaserver），
MVP 阶段不拆。

## 确定性引擎

- 定点数 `FP_SCALE=1000`（同 funny `server/engine/src/math/fixed.ts`），另加 sin/cos 查表。
- LCG 随机数（同 funny `math/prng.ts`），按子系统拆分随机流，种子由服务器签发。
- 禁用 `Math.random`、`Date.now`、浮点三角/开方，靠源码扫描测试强制检查。
- 2.5D：实体有 `x`（水平）、`y`（纵深）、`z`（高度）。屏幕坐标 `screenY = y - z`，按 `y` 排序绘制。
  攻击命中 = x 方向重叠，且 y 差在纵深容差内，且 z 方向重叠。
- 步进顺序：输入 → 状态机 → 移动/重力 → 判定框碰撞 → 伤害/硬直/浮空 → AI → 刷怪/房间逻辑 → 事件。
- 招式是数据：逐 tick 的动画帧、攻击框、受击框、取消窗口、hitstop、击退向量。
- 状态是纯数据（数字、字符串、数组、普通对象；随机数流也存成数字），快照就是一次深拷贝（`engine/snapshot.ts`）。
  MVP 规模（1 名主角 + 十来只怪）下每帧拷贝足够快；实体多了再换 TypedArray。
- 黄金回放测试：固定输入序列，每 tick 状态 hash 不变。

## 网络：lockstep + 回滚

- 服务器只做节拍器和中继，不需要理解指令内容。帧号由服务器分配：客户端给的帧号只是建议，
  落在允许的超前窗口内就采纳，晚到的顺延，因此客户端没法把输入提前到过去的帧。
- 客户端本地立即执行自己的输入；其他玩家的输入先按"沿用上一帧"预测。服务器确认帧与预测不符时，
  回到那一帧的快照重算。快照环形缓冲约 10 帧。
- 单刷时预测总是对的，只有输入被顺延时才会回滚，所以实际没有操作延迟。
- 每 30 tick 上报一次完整状态 hash（funny 只在局末算一次，太弱）。
- 断线重连：命令日志快进；每个房间通关时存一个快照，不必从第 0 帧重放。
- M1 实现（`server/`、`client/src/net/`）：
  - 协议是 JSON over WebSocket（`server/protocol.ts`），正式版再换 protobuf。指令只在按键状态变化时发，带序号。
  - 服务器按墙钟推帧，每 50 ms 把已定帧下发一次。指令落帧规则：`max(建议帧, 最后已定帧 + 1, 该玩家上条指令帧 + 1)`。
    最后一项保证"迟到的按下和松开"不会挤进同一帧，短按不会丢。
  - 客户端领先服务器约一个往返，再加 4 帧余量：开局按握手测得的 RTT 直接跳到位，之后每 500 ms ping 一次，
    测本地帧与服务器时钟之差，用 ±20% 的步进速度慢慢修正；差太多（比如切走标签页）就直接追帧。
  - 快照环形缓冲 300 帧（10 秒）。比设计的 10 帧大，因为单刷时确认帧本来就落后本地一个往返；MVP 规模下每帧深拷贝很便宜。
  - 每个连接每局一个 verifier worker（设计里是 worker 池，M1 规模没区别）。被标记就当场判本局无掉落，不等通关。

## 反作弊

核心原则是"输入即真相"：客户端只上传按键，伤害、掉落、通关都由模拟计算。

| 威胁 | 对策 |
|---|---|
| 改伤害、无敌、秒怪 | verifier 跟着命令日志做影子模拟；房间通关、Boss 击杀以服务器模拟结果为准，hash 不符判作弊 |
| 加速、离线预先算好完美输入 | 单刷也必须在线走节拍器，帧推进速度由服务器墙钟决定 |
| 预知掉落、刷掉落 | 掉落不在模拟里算：模拟只产出"击杀"事件，服务器复算确认后用秘密随机数抽掉落 |
| 复制物品、改背包 | 背包、强化、交易全部在服务器原子执行 |
| 伪造结算 | 服务器给连接打身份；指令在模拟内部校验，非法指令当无操作；结算前原子预约房间号 |
| 脚本代打 | 分析输入间隔分布与操作频率，异常局保存录像供人工复核 |

funny 的 peer judge（随机挑一个空闲玩家客户端来复算）有串通风险，这里改为服务器 worker 池复算，
且涉及掉落的局全部复算。
