# M1 最小化验证

目标不是做一个小游戏，而是用最少的内容验证三个最大的风险。任何一项验证失败，都要先回头改方案。

## 要验证的三个假设

| 编号 | 假设 | 失败意味着 |
|---|---|---|
| H1 手感 | 30Hz 定点确定性引擎能做出 DNF 式的打击感（hitstop、浮空连击、取消） | 要改逻辑频率或模拟方式 |
| H2 反作弊闭环 | 在线单刷时，服务器复算结果与客户端一致；篡改过的客户端会被识别；掉落只由服务器发放 | 网络/反作弊架构要改 |
| H3 水墨美术 | AI 能稳定产出同一风格的水墨角色；抠图、骨骼拆件可行；在场景里看得清 | 换风格或换出图方式 |

## 内容范围

只做这些，其他一律不做：

- 1 个职业（剑客）：移动、奔跑、跳跃、普攻三连、跳斩、上挑（浮空）、1 个突进技能
- 1 种杂兵（近战）+ 1 个木桩
- 1 个地下城，2 个房间：清完怪开门 → 第 2 个房间 → 通关结算 → 掉落 1 件装备
- 背包只显示拿到的装备，不做穿戴和养成

## 技术范围

- `engine/`：定点数、PRNG、2.5D 移动与重力、状态机、判定框、伤害/硬直/浮空、杂兵 AI、房间逻辑、状态 hash、快照/恢复。
- `client/`：Pixi v8 渲染（先用色块，H3 通过后换成正式美术）、键盘输入与输入缓冲、tick 插值、
  hitstop/震屏/闪白/伤害数字、预测与回滚、离线模式（`?offline`）。
- `server/`：一个 Node 进程，内含节拍器中继（WS）、verifier（worker 线程跟随命令日志复算）、
  掉落与背包（先存内存 + JSON 文件）。
- 不做：微信构建、组队、PvP、账号系统（用设备 ID）、拆服务、数据库。

## 验收标准

- H1：不看说明就能打出"普攻三连 → 上挑 → 空中追击"的连段；hitstop、击退、浮空的手感由用户亲自确认。
- H1：黄金回放测试通过，同一输入序列在客户端和 Node 里每 tick 的 hash 一致。
- H2：在线单刷，客户端通关后 1 秒内服务器给出复算一致的结果并发放掉落。
- H2：带 `?cheat=dmg`（本地伤害 ×10）的客户端，在第一个状态 hash 上报点就被服务器标记，不发放掉落。
- H2：本地人为制造 150ms 网络延迟时，单刷操作仍然没有可感知的延迟（输入在本地立即生效）。
- H3：见 ART.md，风格定稿 + 剑客骨骼能播放待机/跑/攻击 + 杂兵帧序列 + 场景可读性测试通过。

## 进度

- [x] 引擎：定点数、PRNG、2.5D 物理、状态机、判定、hitstop、浮空/弹地/倒地、杂兵 AI、房间、hash、快照、bot。18 个测试通过。
- [x] 离线色块客户端（`npm run dev`，http://localhost:5180）。开关：`?dungeon=training`、`?bot`、`?debug`、`?cheat=dmg`、`?seed=N`、`?poses`（主角用姿势图）、`?zoom=N`（跟拍主角）。
- [x] H1 手感：用户试玩后认为"整体感觉对了"（2026-10-08）
- [ ] 服务器节拍器 + verifier + 回滚（H2）
- [x] 美术 R3a：每个动作一张静态姿势图，已放进游戏
- [x] 美术 R3：人偶 A-pose → 拆件 → 骨骼，主角已在游戏里用骨骼动画（走跑不再滑步）
- [ ] 美术 R3：山贼骨骼或帧序列、场景可读性复测（H3）

## 顺序

1. 引擎 + 离线客户端（色块）→ 调手感（H1）。美术风格测试同时进行（H3）。
2. 服务器节拍器 + verifier + 回滚（H2）。
3. 换上正式美术。
